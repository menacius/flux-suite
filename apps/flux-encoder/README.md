# Flux Encoder

**Current version:** `2026 - v0.8.18-alpha`

Flux Encoder is a cross-platform, queue-based media encoder and renderer for Windows and Linux. Its workflow is inspired by professional queue applications such as Adobe Media Encoder, while its compact Qt interface reuses the widget language developed for Flux Motion.

The application uses the Flux Motion graphite theme with the Flux Encoder accent color `#42a274`, the bundled Satoshi font family, and dedicated Flux Encoder icon, splash, and About artwork.

## Development version 001

This first implementation includes:

- Persistent SQLite render queue with crash recovery.
- Separate worker executable so a failed encoder does not crash the GUI.
- FFmpeg and FFprobe discovery.
- Runtime capability probing for CUDA/NVENC, Intel QSV, AMD AMF and Linux VAAPI.
- Built-in software, broadcast, editing and hardware-accelerated profiles.
- Hierarchical render-profile categories.
- User-created categories and editable custom render profiles.
- Immutable profile snapshots inside queued jobs.
- Drag-and-drop media import.
- Atomic temporary output followed by final-file rename.
- FFmpeg progress, speed and ETA reporting.
- Software fallback when a hardware encoder is unavailable.
- Flux Motion-derived `FluxSwitch`, `FluxCaretButton` and `FluxCollapsiblePanel` controls using the active Qt palette.

## Requirements

- CMake 3.21 or newer.
- A C++20 compiler.
- Qt 6.5 or newer with Core, Widgets, SQL, Concurrent and SVG.
- FFmpeg and FFprobe available on `PATH` or placed beside the application.
- SQLite Qt driver (`QSQLITE`).

Hardware profiles depend on both the installed FFmpeg build and the corresponding GPU driver/runtime. An encoder being compiled into FFmpeg does not guarantee that it can run on the current machine, so Flux Encoder performs a small runtime encode probe.

## Build on Windows

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 `
  -DCMAKE_PREFIX_PATH="C:/Qt/6.8.3/msvc2022_64"
cmake --build build --config RelWithDebInfo
ctest --test-dir build -C RelWithDebInfo --output-on-failure
```

The GUI and worker must remain in the same directory:

- `Flux Encoder.exe`
- `flux-encoder-worker.exe`

## Build on Linux

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build -j"$(nproc)"
ctest --test-dir build --output-on-failure
```

For VAAPI, the user must have permission to access a render device such as `/dev/dri/renderD128`.

## Profiles and safety

Profiles store structured settings and argument arrays. They are passed to `QProcess` directly; no shell is invoked. Queue jobs store a complete profile snapshot and revision, so editing a profile cannot silently alter jobs that are already queued.

## Current limitations

Development version 001 schedules one worker at a time. Parallel resource-aware scheduling, full source probing, watch folders, advanced color/HDR controls, profile bundle import/export and Flux Motion render-provider plugins are planned for later milestones.

## Render Provider SDK

Development Version 011 introduces the stable preparation layer for project renderers such as Flux Motion. Providers are discovered from the `providers` directory, validated against Flux Encoder Provider ABI v1, and are expected to run out of process. The included Flux Motion manifest is a placeholder only: **Add Render Project** remains disabled until a compatible headless Flux Motion provider executable is installed.

Presets can now be dragged from Preset Browser directly onto a Queue row. Dropping onto a selected row applies the preset to the whole current selection.

Flux Encoder encodes a short segment around the playhead with the current codec and output settings, then decodes the corresponding frame for display. ### Metadata and resolution controls

Export Settings includes an professional Metadata Export dialog and linked Width/Height controls with Match Source and independent override checkboxes.

### professional encoding selection

In Export Settings, **Format** selects the codec family and output container. Users no longer edit raw FFmpeg encoder names. **Performance** selects Software Encoding or a compatible Hardware Encoding path; Flux Encoder resolves NVENC, Intel Quick Sync, AMD AMF, or VAAPI from runtime capabilities and stores the resolved encoder in the profile snapshot.
## Development Version 020

Export Settings now uses a format-aware Preset dropdown. **Custom** is always the first option, while the rest of the list is filtered to presets compatible with the selected Format. The preview workspace now opens on **Output** by default, followed by Source and Compare.


## Development Version 021

Export Settings UI state now persists between sessions. The hard-coded timecode overlay uses the same FFmpeg filter in final rendering and compressed Output Preview, and preview segments advance the timecode to the actual playhead position.

### Build with WSL and Ubuntu LTS

From PowerShell on Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\build-wsl-ubuntu-lts.ps1
```

A clean build can be requested with `-Clean`. The script detects or installs the requested Ubuntu LTS WSL distribution, installs Linux build dependencies, provisions a compatible Qt 6 SDK when the Ubuntu packages are too old, runs the tests, and creates `dist/Open_Media_Encoder_WSL_Ubuntu_LTS.tar.gz`.
